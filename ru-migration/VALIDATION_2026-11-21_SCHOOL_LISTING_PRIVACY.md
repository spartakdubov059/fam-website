# Перенос закрытия школьной доски объявлений

Дата: 21 ноября 2026 г.

## Источник изменения

В upstream `main` `147ec7903148bfface274c4e681aabb299252dcf` добавлена миграция `20261121190000_restrict_listings_to_authenticated_same_school.sql`. Она разрешает читать активные объявления только вошедшим пользователям с профилем той же школы; автор сохраняет доступ к своим записям. Гостевой экран показывает предложение войти. Новый production workflow Netlify из этой версии в RU-копию не переносится.

## Что изменено в RU

- `GET /api/v1/listings` аутентифицирует пользователя и получает его school scope из активного профиля базы. Для гостя или профиля без школы возвращается пустой список без чтения объявлений.
- YDB repository требует `school_id` и применяет `WHERE school_id = ? AND status = 'active'`; школа из параметров запроса не принимается.
- Одобренное фото активного объявления также выдаётся только вошедшему участнику школы объявления; фото другого школьного раздела и гостю возвращается как недоступное.
- Браузер отправляет same-origin cookie. Гость получает понятный экран входа через Яндекс ID, участник видит обычное пустое состояние, если у школы нет активных объявлений.
- Добавлены синтетические тесты гостевого отказа, отсутствующего профиля, передачи серверного school scope в repository, SQL-фильтра YDB, гостевого экрана и доступа к фото между школами.

## Проверка

На Node 22.15.0 локальный backend/UI suite: **430/430** до добавления photo same-school regression; повторный полный прогон выполняется. SDK/Sharp verifier: `SDK_COMPAT_PASS`. Переносимый validator расписаний: **8 timer-файлов**. `git diff --check` прошёл. Внешняя одноразовая YDB CI ещё не запускалась для этого изменения; российский cloud staging не создавался.

Проверен только новый upstream privacy control. Это не доказывает полный parity с FAM: прочие экраны, все SQL/RLS/RPC/trigger правила, фоновые задания и staging остаются предметом дальнейшей сверки. `main`, production и реальные пользовательские данные не изменялись.
