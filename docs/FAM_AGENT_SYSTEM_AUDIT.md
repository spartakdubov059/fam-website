## Проверенные факты

- PR Manager в PR #65 ждёт required check `Russian content safety tests` через `gh pr checks --required`, не запрашивая actions:write. Regression workflow включает все разрешённые пути `css/**`, `js/**`, `assets/**`, `docs/**`. Любой агентский PR создаётся draft; workflow сам не вызывает ready/merge. Это снижает риск случайного merge, но не заменяет server-side review gate, так как токен имеет `pull-requests:write`, а ruleset требует 0 одобрений. CI [#43398041367](https://github.com/spartakdubov059/fam-website/actions/runs/43398041367) и PostgreSQL 17 integration [#43398041286](https://github.com/spartakdubov059/fam-website/actions/runs/43398041286) прошли.

- Активны функции `fam-agent-worker` v17 и `fam-agent-coder-bridge` v1; bridge отвечает за узкое claim/finish API, но не выполняет модель сам. Новые `report`/`save_report` маршруты PR #65 в production не развернуты.

## Следующий безопасный этап

1. Полный успешный production-queue → Qwen → QA → draft PR путь остаётся недоказанным: Qwen smoke использовал synthetic fixture, не production task. Нынешний GitHub connector не даёт workflow-dispatch; дополнительный длительный model run не запускался.
2. Просмотреть PR #65: Reporter CI зелёный, но daily production report зависит от ручного review и отдельного rollout миграции + bridge.
3. Просмотреть PR #74: PostgreSQL 17 integration CI и текущие проверки прошли; bounded retry migration не применялась.
4. Владелец должен отдельно решить обязательное одобрение; ruleset допускает 0 reviews, а инструменты не дают изменять ruleset.
5. Разобрать advisories `pg_net`, публичный `report_fam_site_error` и Auth; не менять production/Auth/RLS/grants без отдельного решения. Не объединять PR и не выкатывать production.
