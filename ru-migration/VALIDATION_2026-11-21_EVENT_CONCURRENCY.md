# Повторы YDB для регистрации на события — 21 ноября 2026

Исходный Supabase workflow сериализует запросы к местам события и при конкуренции возвращает результат проверки вместимости. YDB выполняет serializable-транзакции оптимистично: конфликтующие транзакции могут завершиться `Transaction locks invalidated`. В RU SDK `sql.begin()` по умолчанию не повторяет такие транзакции; повторы допускаются с `idempotent: true`.

Для RU регистрации, отмены записи и решения организатора включён повтор всей транзакции. Повтор безопасен: callback заново читает состояние заявки и счётчик, а повторно выполненное действие останавливается на уже изменённом статусе.

Проверки на Node 22.15.0:

- Полный backend suite: **417/417**.
- Новые тесты проверяют передачу `idempotent: true` для регистрации, отмены и решения организатора.
- `ru-migration/compat/integration-ydb.mjs` содержит синтетическую гонку двух пользователей за последнее место и проверяет, что ровно одна регистрация успешна, счётчик равен 1. Сам integration сценарий для этого локального изменения не запускался.
- `ru-migration/compat/verify.mjs` и `git diff --check` прошли.

YDB retry semantics: [настройка режима транзакции](https://ydb.tech/docs/en/recipes/ydb-sdk/tx-control), [конфликты конкурентных транзакций](https://ydb.tech/docs/en/concepts/transactions). Облачное staging, CI для текущего изменения и реальные пользовательские данные не использовались.
