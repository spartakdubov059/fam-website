# FAM RU — изолированная миграция на российскую инфраструктуру

**Рабочая ветка: `migration/yandex-cloud`. Не сливать в main и не развёртывать на production.**

Цель — подготовить российскую копию FAM отдельно от действующего сайта. Ветка `main`, текущий FAM, Netlify/Supabase и реальные данные учеников не используются для этих проверок.

## Подтверждено сейчас

- Последняя полная проверка: **63/63 backend-тестов**, YDB/AWS SDK и Sharp 0.35.5 прошли на Node 22 ([SDK/тесты](https://github.com/spartakdubov059/fam-website/actions/runs/43454552356)).
- GitHub Actions [local YDB integration](https://github.com/spartakdubov059/fam-website/actions/runs/43454552347): успешно на одноразовой YDB в GitHub runner, включая отправку объявления через API, отклонение попытки модерации от ученика, одобрение администратором той же школы и публичное чтение только после одобрения.
- Гостевая доска получает только публичный список из российского API, не отправляет cookies и вставляет текст объявлений безопасным DOM API. До настройки backend остальные пользовательские операции остаются отключены.
- YDB зависимости backend зафиксированы точными версиями и lockfile.

## Что уже реализовано в изолированном коде

- Отдельная копия статического интерфейса в `app/web`.
- Fail-closed HTTP backend с API подачи объявления и школьной идеи; идеи без доступной проверки сохраняются только как `pending` и не входят в публичные чтения.
- API избранного: операции выполняются от подтверждённого профиля, а избранными могут быть только активные объявления.
- API отправки личных сообщений: активный получатель должен быть из той же школы; сообщение сохраняется только после явного ответа модерации `ok`.
- OIDC bearer verification, разрешение ролей через профиль в YDB; дополнительно реализован серверный OAuth Яндекс ID с PKCE S256, одноразовой state-cookie, проверкой `client_id` профиля, часовым HttpOnly/SameSite cookie и logout.
- Маршрут школьной модерации объявления: права берутся из профиля YDB, решение ограничено школой объявления и переходом только из `pending`; используется транзакция YDB.
- Добавлен backend-модуль записи на мероприятия: открытые и ограниченные события, одно место на пользователя, транзакционная проверка вместимости, отмена своей записи, публичный счётчик без данных участников и решение владельца мероприятия с ролью школьного администратора/совета.
- YDB схема профилей и объявлений, параметризованный repository; добавлено публичное чтение только активных объявлений с ограниченным набором полей; `/api/v1/me` возвращает профиль из YDB только после проверки OIDC-токена.
- Локальные privacy/moderation gates; новые записи остаются `pending`, если проверка недоступна.
- Обработка изображений через Sharp и адаптер приватного S3-совместимого хранилища; проверены unit-тестами с синтетическими данными и mock storage.

### Подключение Яндекс ID (пока не настроено)

Для отдельного тестового домена нужно зарегистрировать приложение Яндекс OAuth типа «Для авторизации пользователей», добавить HTTPS Redirect URI `https://<тестовый-домен>/auth/yandex/callback` и минимальное право `login:info`. В переменные окружения backend передаются `FAM_RU_YANDEX_CLIENT_ID`, `FAM_RU_YANDEX_REDIRECT_URI` и случайный `FAM_RU_SESSION_SECRET` длиной не менее 32 байт. Секреты не записывать в репозиторий или frontend. Для разработки допустим только `localhost` без HTTPS; удалённый адрес без HTTPS отклоняется.

Обмен кода и запрос профиля выполняются сервером. OAuth-токен не сохраняется и не передаётся в URL; браузеру выдаётся только подписанная краткоживущая HttpOnly cookie. Роли выдаются исключительно из `fam_user_profiles`; сам вход не создаёт школьный профиль и не назначает роль. Реальная регистрация OAuth-приложения и внешний вход не проверялись.

Эти части ещё не образуют полный перенос FAM. Требуются перенос и аудит всех исходных функций, SQL/RLS, ролей и фоновых задач, а также проверка всей пользовательской навигации и сценариев.

## Неподтверждённое / блокеры

- Архив `FAM_RU_Migration_Starter_2026-11-13_220tests.zip` недоступен в текущем workspace; его SHA и заявленные **220 тестов** не воспроизведены. В истории есть только текстовый отчёт, без доступного вложения. Локальные 24 теста — другой, более узкий набор.
- Реального российского облачного staging нет. Яндекс ID flow проверен только mock-тестами, поскольку нет зарегистрированного OAuth-приложения, redirect URI и конфигурации backend. Не проверялись облачная YDB, объектное хранилище, реальный OAuth-провайдер, лимиты расходов или сетевые политики.
- Семь исходных Edge Functions, 69 SQL миграций и расписания pg_cron перенесены не полностью; из `submit-content` пока работают только сценарии объявлений, идей и отправки сообщений. Полная модерация, сообщения, аватары и прочие функции не подключены; см. `PORTING_INVENTORY.md`.
- Публичный просмотр подключён к российскому API; публикация из интерфейса, реальные вход/выход и полноценный moderation UI ещё не готовы для пользователей. OAuth серверный адаптер не работает без регистрации приложения и секретов в отдельном окружении.
- API мероприятий пока не подключён к интерактивному интерфейсу; его YDB-схема и сценарии ожидают запуска CI на одноразовой базе перед подтверждением совместимости. Запись на мероприятие не является готовой пользовательской функцией.
- Никакие платные ресурсы и trial не запускались. У Yandex Cloud бесплатные объёмы ограничены месячными квотами: после их превышения начисляется плата. Бюджетные пороги только уведомляют и сами по себе не останавливают потребление. Поэтому при требовании строго 0 ₽ облачные ресурсы не создаём; используем только локальную эмуляцию, пока нет подтверждённого способа гарантировать отсутствие списаний. См. [Free tier](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier) и [бюджеты](https://yandex.cloud/ru/docs/billing/concepts/budget).
