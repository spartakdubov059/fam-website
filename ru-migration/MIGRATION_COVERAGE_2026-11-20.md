# Карта покрытия схемы FAM RU

Снимок перепроверен 20 ноября 2026 г. по GitHub refs: FAM `main` `af1f0086066d18b3d814dd535f06eda733ae58de`, код RU `migration/yandex-cloud` `ba44454d82cbf179f240940846bbc9e45ea0e7f2`. В актуальном дереве `main` — 78 файлов Supabase SQL migrations и 7 Edge Function entrypoints; RU содержит 33 YDB schema files. Количество файлов не подтверждает эквивалентность: Postgres RLS, RPC, триггеры, cron и очереди требуют проверки поведения отдельно.

YDB API требует активную роль школьного администратора или Совета и ограничивает чтение/изменение школой из DB-профиля. Каждое изменение записывает только метаданные действия, без текста идеи.

## Части, которые нельзя считать перенесёнными целиком

- Политики доступа Supabase (RLS), grants и триггеры: в RU это серверная Node.js/YDB логика; соответствие каждого исходного разрешения и запрета пока не доказано. Индексы из `20261109134755_add_missing_school_workflow_foreign_key_indexes.sql` добавлены в `schema/29_fk_lookup_indexes.yql` и применены в disposable YDB CI, но cloud query plans и индексная нагрузка не проверены.
- RPC/functions: нужен построчный список исходных SQL-функций с указанием RU endpoint/repository, теста и оставшегося отличия.
- Изменения исходной схемы после существующего crosswalk: нужно сопоставить каждую миграцию с RU схемой и поведением, а не только искать похожие названия таблиц.
- Внешняя автоматическая модерация и модельные workers заменены ручными или агрегированными путями ради бесплатного режима; это функциональные отличия.
- Облачные Yandex ID, YDB и S3, провайдерская проверка свежей аутентификации и российский staging не настроены/не проверены. Реальные данные не подключались.

## Критерий закрытия миграции

Для каждого исходного SQL-файла создать запись с объектами (таблица, индекс, функция/RPC, trigger, policy, cron), RU-аналогом, тестом на синтетических данных и решением: `эквивалент`, `безопасная замена с отличием` или `не перенесено`. Сначала закрывать безопасность/идентичность/доступ к школьным данным, затем API и фоновые jobs. Не включать расписания и не подключать реальные данные, пока все относящиеся к сценарию проверки не пройдены.


## Проверенная квота сообщений/идей (20 ноября 2026)

По исходной миграции `supabase/migrations/20261108004943_enforce_server_side_content_moderation.sql` повторно сверены серверные пределы: 5 объявлений/час, 5 идей/час и 8 одобренных сообщений/минуту. RU ранее разрешал 10 идей/час, а прямые одобренные сообщения не имели такой же минутной квоты. Теперь YDB транзакционно применяет эти пределы через `fam_submission_quotas`; ручная очередь сообщений сохраняет более строгий предел 5 за 24 часа. Синтетические unit и disposable YDB проверки добавлены. Это доказывает только данную квоту и не закрывает остальные policies/grants исходной миграции или весь SQL crosswalk.

## Обновление полноты интерфейса относительно актуального main

- Текущий RU frontend состоит из `ru-migration/app/web/index.html`, `shell-bootstrap.js`, модулей доски/профиля/сообщений/афиши и backend API. В этой ревизии подключён существующий `profile-settings.js` (редактирование имени, фамилии, класса и типа участника), а категория событий получила отдельную кнопку «Афиша», фильтрующую строго по `is_event`. В ограниченных мероприятиях свободные места можно запросить отдельно через активный event occupancy API; запрос не выполняется для всех карточек автоматически. Подключена фиксированная мобильная навигация к доске, Афише, сообщениям и профилю; главная страница использует шесть локальных баннеров с ручными кнопками и доступными точками карусели. UI tests и shell isolation test проходят. В профиле доступна закрытая история своих идей (до 50 записей) со статусами модерации; фото выдаются только через owner-checked приватный image route, а мобильная кнопка профиля ведёт к истории для авторизованного пользователя. Это рабочая изолированная оболочка, но она не является полным переносом 311 KB исходного `index.html` SPA.
- Main commit [5496264](https://github.com/spartakdubov059/fam-website/commit/5496264560890d438b93191cbc7340e8ec75e0cd) добавил/изменил mobile tabbar, Afisha cards для announcements/polls, event capacity banners, отображение Afisha при пустом списке объявлений и соответствующие переходы. В RU frontend события фильтруются отдельным списком, а новости и опросы отображаются в школьной ленте перед списком. Мобильная вкладка «Афиша» теперь включает фильтр событий и прокручивает к началу этой объединённой последовательности (новости/опросы, затем события). Проверено на commit `84a8152` тестом навигации и CI. Карточки ещё не сведены в одну визуальную сетку исходной Afisha и визуальное/состояниевое соответствие остаётся неполным.
- Следующая работа по полной копии: составить маршрутную/экранную карту исходного SPA, перенести разделы и состояния в RU-модульную архитектуру и для каждой операции использовать только RU API; затем покрыть браузерными сценариями на синтетических данных. Не копировать Supabase browser client, секреты или production-only domain-sync workflow.
- Полный UI перенос, актуальность всех функций/SQL после `main` `af1f008`, независимый security review и российский облачный staging остаются незавершёнными. Возможность гарантировать облачный staging с расходом 0 ₽ не доказана; см. [проверку бесплатного тарифа и ограничений бюджета](FREE_STAGING_COST_REVIEW_2026-11-20.md).
