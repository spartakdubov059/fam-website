# FAM — доступность из России без VPN

Проверено 17 ноября 2026 года. Цель — доступность FAM для школьного сообщества из обычных российских сетей. Этот документ не содержит данных учеников.

## Подтверждённая ошибка в `main`

`index.html` автоматически перенаправлял всех посетителей GitHub Pages (`https://spartakdubov059.github.io/fam-website/`) на `https://famru.netlify.app/`. В результате старый адрес **не был резервным**: при недоступности Netlify пользователь попадал на тот же недоступный хост.

В PR с этим документом автоматическое перенаправление убрано, а для регистрации используется конкретный разрешённый адрес текущей площадки. **До выкладки это только кандидат на исправление.**

## Реальные точки отказа

1. Netlify / GitHub Pages: два зарубежных статических хостинга. Отказ одного не доказывает отказ другого.
2. `cdn.jsdelivr.net` — внешний скрипт `@supabase/supabase-js@2.119.0`. Если он не загрузился, сайт покажет ошибку подключения Supabase, даже когда HTML доступен.
3. `tfacqpljrvfpcrhdovbu.supabase.co` — иностранный backend: вход, база, функции и Storage. Если до API не доходит трафик, смена только HTML-хостинга не восстанавливает функции.
4. Возможны разные сбои на провайдерах, Wi-Fi и мобильной сети; проверка с иностранного сервера не заменяет пользовательскую проверку.

## Перед включением резервного домена

1. Supabase → Authentication → URL Configuration → Redirect URLs: должны быть оба адреса:
   - `https://famru.netlify.app/`
   - `https://spartakdubov059.github.io/fam-website/`
   Не разрешайте произвольные домены или `**` в production.
2. Email Templates: если есть собственный шаблон подтверждения, он должен использовать `{{ .RedirectTo }}`, а не принудительно `{{ .SiteURL }}`.
3. Проверить тестовый вход и регистрацию на обоих адресах, чтобы новый пользователь остался на своём хосте. Сессии браузера разделены по origin; при переходе между доменами повторный вход возможен, но аккаунты, объявления и сообщения находятся в общей базе.
4. Проверить с реальных российских устройств **без VPN**, по крайней мере один школьный/домашний Wi-Fi и один мобильный оператор. Фиксировать только URL, текст ошибки, время, тип сети и результат: «не открывается», «открывается, но не работает вход», «работает». Не запрашивать логины, письма подтверждения, токены, HAR-файлы с данными или личную информацию школьников.
5. Перед релизом проверить полный CI, защищённые файлы и конфликтующие PR.

## Если проблема повторяется

- Не открывается ни главная, ни текст ошибки: проверить доступность хоста, HTTPS и DNS отдельно.
- Главная открывается, но не работает вход: отдельно проверить `cdn.jsdelivr.net` и `*.supabase.co`, не удалять пользовательские данные или сессии автоматически.
- Только один оператор видит ошибку: вероятен сетевой/маршрутный фактор; не объявлять всеобщую блокировку домена без проверки.
- Не подменять недоступный Netlify ссылкой, которая автоматически ведёт обратно на Netlify.

## Постоянное решение

Для устойчивой доступности в России необходима проверенная российская статическая площадка **и** доступный из РФ backend, а не просто новый домен. Есть GitVerse Pages Free для статических сайтов, но им нужна отдельная репозиторная публикация и проверка входа/API; этот сервис не переносит Supabase автоматически. Yandex Cloud Object Storage требует отдельного платёжного аккаунта и тарифицируемых ресурсов. Перед миграцией любых персональных данных школьников требуется согласовать правовую сторону и безопасный порядок переноса.

Рабочие домены не переключать, пока нет проверенной альтернативы и не пройдены end-to-end тесты.
