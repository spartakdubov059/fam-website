# Сверка FAM `main` и RU-ветки

Сверка выполнена 20 ноября 2026 по актуальным ссылкам GitHub: FAM `main` `5e749c56b9270efbfdf1f48cefe6e8d95a01c579`, исходная `migration/yandex-cloud` `2795f05a9f79376a91a2f76bf0d0e29664861ce0`, RU feature `2a009bf416330a4383905b5e5d45deb1527e3edf`. Эти три указателя проверены независимо. `main` и `migration/yandex-cloud` не изменялись.

Старая российская ветка создана от исходной миграционной ветки, а не от нынешнего `main`. Между теми upstream-коммитами есть 9 новых SQL-миграций и 6 изменений Edge Functions. Ниже проверен их смысловой эквивалент в YDB/API. Это crosswalk функций, а не утверждение о построчном совпадении SQL, RLS, триггеров или интерфейса.

## Изменения Edge Functions

| Edge Function upstream | Что делает текущий upstream | Российская реализация |
|---|---|---|
| `council-management` | Убирает email из административных ответов | RU-модель профиля и административные ответы не используют email; личность/школа извлекаются из серверной Yandex/OIDC сессии. Проверку всех UI ответов следует считать частью полного security review. |
| `fam-listing-image-worker` | Обрабатывает очередь изображений объявлений, идей и аватаров с вызовом модерации | RU имеет приватное хранилище и раздельные очереди/ручную модерацию. Автоматический внешний AI намеренно не переносится: он требует платного внешнего API и расходится с условием 0 ₽. |
| `moderate/image-reviewer.ts` | Общие визуальные проверки для фото и аватаров | В RU нет внешнего классификатора; файлы декодируются/перекодируются Sharp и ждут решения уполномоченного школьного модератора. Это намеренная замена способа модерации, не функциональная идентичность. |
| `moderate/index.ts` | Добавляет проверки изображений идей к общему endpoint | RU изображения идеи проходят очередь ручного одобрения, фото недоступны до одобрения. Нет внешнего AI-проверщика. |
| `school-admin-access/access-controls.js` | Возвращает имена/класс заявителя вместо email | RU использует school-scoped списки заявок/участников; точные UI сценарии и минимизация выдаваемых полей требуют финального просмотра перед staging. |
| `submit-content/index.ts` | Проверяет сигнатуры загружаемых изображений и добавляет загрузку фото идей | RU принимает сырой файл только в аутентифицированном API, проверяет формат по декодеру Sharp и превращает его в ограниченный WebP до записи в приватный S3. Unit/Sharp CI проверяет формат, размер и декодирование. |

## Что это означает

- Основные пользовательские сценарии этих 9 миграций представлены в RU-коде, но исходные Supabase-миграции нельзя применить к YDB. Остаётся отдельная работа по полноте соответствия всех 78 migrations, RPC, RLS, триггеров, семи Edge Functions, экранов и переходов.
- В RU-ветке источник upstream разделён: часть сценариев реализована, часть сознательно имеет безопасный ручной аналог из-за бесплатного лимита. Это не полная копия поведения `main` и не доказательство готовности для реальных пользователей.
- Российский staging не поднят: нет проверенной гарантии расхода 0 ₽, настроенных Yandex OAuth, YDB, S3, домена/хоста. Реальные аккаунты и данные учеников не использовались.
- До исправления отсутствующих звеньев, независимого security review и staging QA публикация и подключение реальных данных остаются закрыты.
