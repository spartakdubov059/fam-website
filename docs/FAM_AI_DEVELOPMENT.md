# ИИ-разработка FAM: безопасный процесс

Обновлено: 11 ноября 2026 года.

## Цель

Дать FAM облачного ИИ-разработчика, который по конкретному заданию может прочитать исходники сайта, подготовить небольшое изменение, проверить его и передать владельцу в отдельном Pull Request. Рабочий сайт не редактируется напрямую.

## Что уже есть

- Единая ежедневная ChatGPT-автоматизация проверяет состояние FAM и формирует один отчёт в ChatGPT.
- Supabase Worker — детерминированный исполнитель четырёх разрешённых типов технических задач. Он не генерирует код.
- GitHub Actions выполняет обычные тесты для Pull Request.
- Codex Action подготовлен как отдельный ручной ИИ-разработчик, который работает в изолированной копии репозитория.

## Как будет работать Codex-разработчик

1. Владелец вручную запускает workflow **FAM Codex developer** из GitHub Actions на ветке `main` и передаёт конкретное задание.
2. GitHub-hosted runner получает копию основной ветки без сохранённых GitHub credentials.
3. Codex получает доступ только к рабочей копии. Для него включён профиль `:workspace`, без прямого сетевого доступа. Используется официальный `openai/codex-action`, закреплённый на commit SHA, и фиксированная версия CLI.
4. Разработчик может менять только `index.html`, `css/`, `js/`, `assets/`, `docs/` и `tests/`.
5. Patch передаётся в отдельное задание без OpenAI API key. Там применяются регрессионные тесты, проверка синтаксиса JavaScript и проверка путей.
6. Только если все проверки прошли, третье изолированное задание с правами записи создаёт **черновой Pull Request**. Оно не запускает тестовый код и не выполняет исходники из patch.
7. Pull Request остаётся черновиком. Никакого автоматического merge, deployment или изменения production нет. После проверки владелец отдельно решает, объединять ли его.

## Какие права разделены

- Задание Codex: только `contents: read`, нет GitHub token с правом записи в рабочей среде модели.
- Проверка patch: только чтение репозитория, нет OpenAI API key и нет GitHub credentials для записи.
- Создание чернового PR: только `contents: write` и `pull-requests: write`; выполняет статические git/gh-команды, не запускает код из patch.
- В workflow нет команды merge и нет команды deployment.
- Запуск разрешён только вручную владельцу репозитория `spartakdubov059`, с ветки `main`.

## Требуется для первого запуска

- PR с этим workflow должен быть проверен и отдельно объединён владельцем. До этого workflow не появится в Actions на основной ветке.
- В репозитории должен быть настроен секрет GitHub Actions `OPENAI_API_KEY`. Сам ключ не вводить в ChatGPT, PR, issue или код.
- Codex Action обращается к OpenAI API. **API-использование оплачивается отдельно и не входит автоматически в подписку ChatGPT.** До настройки ключа и подходящего бюджета workflow не запускайте. Платёжные настройки и секрет должен настраивать ответственный владелец проекта; лимит расходов нужно проверить заранее.
- В настройках GitHub Actions может потребоваться разрешить workflow создавать Pull Requests: Settings → Actions → General → Workflow permissions → Allow GitHub Actions to create and approve pull requests. Это право не требуется агенту Codex и используется только финальным заданием, которое открывает черновой PR.

## Что пока не автоматизировано

- ChatGPT-отчёт и Codex workflow пока не связаны так, чтобы ежедневная автоматизация сама запускала Codex. Это отдельный ручной старт.
- Это первая безопасная версия с одним Codex-сеансом, выполняющим последовательные роли планировщика, разработчика, рецензента безопасности и тестировщика. Это не четыре независимые модели. Отдельных субагентов можно подключить позднее, после проверки стоимости, качества и доступа.
- Workflow не может объединять PR, изменять базу данных, обновлять Edge Functions или выкладывать сайт.
