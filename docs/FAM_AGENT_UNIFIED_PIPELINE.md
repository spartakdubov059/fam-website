# FAM — единая цепочка технических агентов

Статус: кандидат внедрения; до публикации новой версии Supabase Edge Function и успешного CI подключение штаба к очереди не считается рабочим.

## Как проходит задача

1. Сайт записывает **только фиксированные коды** клиентских ошибок и разделы интерфейса в агрегированную таблицу Supabase. Ни тексты сообщений, ни профили, ни произвольные логи туда не попадают.
2. Действующий cron `fam-agent-coder-task-producer` в 03:10 UTC проверяет агрегаты за 24 часа. При пороге 3+ события создаёт **не более одного активного** разрешённого технического задания `coder_patch_request` в закрытой очереди. Никаких произвольных инструкций из пользовательских данных.
3. GitHub Actions `fam-codex-developer.yml` в 03:15 UTC (или по ручному запуску) через защищённую Edge Function `fam-agent-coder-bridge` запрашивает только `id, task_key, event_code, page_area, occurrences`. Отсутствие задания — нормальное состояние, запускается безопасный локальный аудит.
4. **Qwen 3.8** получает только заранее утверждённый шаблон задачи и разрешённые исходники. Самостоятельно предлагает diff; не меняет базу, Auth, модерацию или защищённые тесты.
5. Отдельный GitHub job **без секретов** проверяет применимость diff, область правки, регрессионные тесты и синтаксис. После этого открывается **PR**, который не объединяется автоматически. Публикация только по решению владельца.
6. **ARBITER, INSPECTOR, RECRUITER и INTEGRATOR** в `fam-agent-governance.yml` контролируют GitHub PR и состояния workflow. После внедрения данной ветки штаб дополнительно запрашивает **только агрегаты** очереди через `POST {action:"health"}` по уже защищённому каналу. Результаты становятся отдельной секцией отчёта; превышения порогов создают или обновляют контрольную GitHub Issue.

## Защита данных

- Edge Function принимает `POST`, отклоняет браузерный `Origin`, требует `x-fam-agent-token` и вызывает **строго определённый** RPC `get_fam_agent_queue_health()` под серверным ключом.
- Возвращаются лишь **шесть ограниченных счётчиков**: `queued`, `claimed`, `in_progress`, `failed_last_24h`, `expired_leases`, `oldest_queued_minutes`.
- Ни `payload`, ни `task_id`, ни `user_id`, ни содержание публикаций или сообщений, ни секреты не передаются в GitHub Issue или модели.
- Токен хранится только в GitHub Actions Secrets и Supabase Secrets. Работа штаба с Supabase разрешена **только в job main**, а не на PR с непроверенным кодом. При отсутствии настройки статус «не подключено», при сбое — «недоступно»; это **не** статус «здорово».
- Общий токен моста также позволяет действующим действиям `claim/finish`, поэтому он не должен передаваться в модель или произвольные действия GitHub. В дальнейшем его следует заменить отдельным read-only секретом с более узкими правами.
- `model_completed` в Supabase означает только «модель завершила анализ; предложенный patch ожидает независимой QA», а **не** «код исправлен в production». Источник истины о готовности — GitHub independent QA и утверждённый PR.
- Штаб ничего сам не объединяет, не нанимает и не публикует.

## Активация и проверка

1. Объединить PR только после независимого CI и проверки прав.
2. Развернуть обновлённую `fam-agent-coder-bridge` с прежней обязательной серверной авторизацией (`verify_jwt=false`, внутренний токен обязателен).
3. Проверить безопасный `health` и отказ при неверном токене без вывода секрета; подтвердить, что возвращаются только шесть чисел.
4. Запустить контролирующий GitHub Actions workflow на `main`; убедиться, что появился раздел «SUPABASE» с состоянием `connected` либо честным объяснением, почему соединение отсутствует.
5. Проверить чтение очереди Qwen и нормальный результат `no task` при отсутствии пороговых событий. Не создавать вымышленные ошибки, не загружать пользовательские данные для искусственной демонстрации.
6. При сбое оставить рабочий школьный сайт, данные и основной контур модерации без изменений; откатить только новую функцию health или её вызов через отдельный проверенный PR.

## Ограничения

Штаб не читает исходные ошибки Supabase напрямую, не создаёт произвольные задачи для модели и не может запускать платные LLM. Обнаруженные ошибки самого Qwen требуют человеческого анализа либо отдельной безопасной диагностики, а не бесконечной передачи той же модели. Это намеренный контроль риска и лимитов GitHub Actions.
