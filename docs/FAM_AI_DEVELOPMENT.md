# Облачная ИИ-разработка FAM без платных API

Обновлено: 11 ноября 2026 года.

## Что работает

- Supabase Worker — детерминированный исполнитель четырёх заранее разрешённых технических задач. Он не генерирует код.
- Единый ежедневный отчёт ChatGPT проверяет состояние сайта, GitHub и Supabase.
- Отдельный GitHub Actions workflow **FAM local AI developer** использует локально запущенную модель Qwen2.5-Coder-7B-Instruct-GGUF через llama.cpp. Для кодирования не используются OpenAI API, API-ключи или платный inference-провайдер.
- Репозиторий FAM публичный. GitHub указывает, что стандартные GitHub-hosted runners для публичных репозиториев бесплатны; runner ubuntu-latest имеет 4 CPU и 16 GB RAM.
- Модель Qwen2.5-Coder-7B-Instruct-GGUF распространяется под Apache 2.0. Файл Q4_K_M размером 4.68 GB загружается во временную среду GitHub Actions, его SHA-256 проверяется до запуска, веса не добавляются в репозиторий.

## Как работает локальный ИИ-разработчик

1. По расписанию ежедневно в 06:15 MSK, по ручному заданию или после изменения самого workflow/валидатора GitHub Actions получает копию основной ветки.
2. Runner загружает бесплатные веса Qwen и запускает их локально через llama.cpp. Исходный код передаётся только процессу модели на том же временном runner.
3. Модель планирует, какие разрешённые файлы нужны, получает только относящиеся к задаче фрагменты, формирует unified diff и краткий отчёт.
4. Скрипт проверяет структуру patch и разрешённые пути.
5. Отдельный job без секретов и права записи применяет patch, запускает все имеющиеся регрессионные тесты и проверяет синтаксис JavaScript.
6. Низкорисковый patch после независимого CI может быть объединён автоматически. Затем workflow запрашивает GitHub Pages build через Pages API, сверяет commit SHA и проверяет HTTP-ответ production. Если тесты, merge, build или HTTP-проверка не проходят, workflow останавливается.
7. Если модель сообщает средний/высокий риск, patch затрагивает защищённые действия или проверки не проходят — изменение не публикуется; оно может быть передано как черновой PR для ручного решения.
8. Никаких действий по аккаунтам, санкциям, приватным данным, доступам, Auth, RLS, секретам или производственной базе данных автоматический контур не выполняет. Такие изменения требуют отдельного решения владельца.

## Разделение платных и бесплатных компонентов

- Новый кодирующий workflow работает локально и не использует платные API.
- В существующей серверной функции модерации FAM уже присутствуют OpenAI-компоненты. Этот новый workflow их не подключает, не расширяет и не меняет. Поэтому бесплатность нового контура не означает, что вся текущая платформа FAM уже гарантированно не обращается к внешним API.
- Не добавлять новые платные API, платные модели, платные хостинги или платные сервисы в контур разработки.

## Что нужно помнить

- Открытая модель меньше и слабее крупных облачных ИИ-систем. Она может ошибаться, выдавать неподходящий patch или не справиться со сложной задачей; поэтому работают ограничения путей и независимые тесты.
- Это один локальный кодирующий LLM с несколькими последовательными этапами, а не множество независимых моделей.
- Сложные backend-изменения, миграции и изменения безопасности остаются вне автоматического контура до отдельной архитектуры и тестовой среды.
- Автоматическая публикация разрешена только для ясно низкорисковых изменений разрешённых файлов и только после полного успешного набора проверок.
- При любом сомнении, плохом результате тестов, конфликте основной ветки или неуспешной публикации workflow останавливается.
