# Сверка FAM `main` и RU-ветки

Сверка исходных изменений выполнена 20 ноября 2026. Проверенные указатели GitHub: FAM `main` `af1f0086066d18b3d814dd535f06eda733ae58de`; проверенная RU-ревизия кода `c3b90e2658802220984f4d3915828f6082f433fe`, текущая вершина ветки содержит последующие документальные записи. `main` не менялась этим переносом; RU-ветка изолирована. Эта таблица сохраняет исходный crosswalk девяти SQL-миграций и шести изменений функций; актуальная сверка всех семи Edge Function entrypoints и их отличий добавлена в [EDGE_FUNCTION_COVERAGE_2026-11-20.md](EDGE_FUNCTION_COVERAGE_2026-11-20.md). Это не построчная проверка всех последующих изменений `main`.

Старая российская ветка создана от исходной миграционной ветки, а не от нынешнего `main`. Между теми upstream-коммитами есть 9 новых SQL-миграций и 6 изменений Edge Functions. Ниже проверен их смысловой эквивалент в YDB/API. Это crosswalk функций, а не утверждение о построчном совпадении SQL, RLS, триггеров или интерфейса.

## Что это означает

### Сверка клиентских итогов опросов (20 ноября 2026)

- В актуальной FAM `school-pulse.js` распределение ответов видно только проголосовавшему участнику или после закрытия опроса, и только при пяти и более голосах.
- RU API уже возвращал `counts` только от пяти голосов, но клиент показывал это распределение всем участникам открытого опроса. На локальной ветке `codex/fam-ru-port-next` исправлено: клиент соблюдает условие «проголосовал или опрос закрыт», проверяет целостность массива счётчиков и показывает процентное распределение. Добавлена регрессионная проверка для открытого, проголосовавшего и закрытого состояний.
- Исходный `fam_pulse_feed()` объединяет школьные объявления с активными мероприятиями без лимита мест. RU endpoint пропускал мероприятия из `fam_listings`; теперь он включает будущие/без даты open-entry мероприятия раньше объявлений, ограничивает описание 450 Unicode-символами и выдаёт только публичную проекцию без владельца и storage key. Добавлен synthetic YDB сценарий для open/capacity/expired событий.
- В upstream `school-pulse.js` гость видит общедоступные мероприятия без лимита мест даже без профиля школы. RU-shell раньше сразу предлагал вход; теперь для гостя используется существующий публичный `GET /api/v1/listings`, показываются максимум шесть активных мероприятий без лимита мест с будущей/неуказанной датой и только их открытые поля. Добавлена UI-регрессия для ограниченного и прошедшего события, обычного объявления и запроса без credentials.
- На локальной версии `ae22ff3` backend suite прошёл `346/346`; после гостевых мероприятий локально прошли `348/348` (включая недоступный public-feed fallback). SDK/Sharp verifier — `SDK_COMPAT_PASS`, portable timer parser проверил 8 файлов. Скрипт YDB integration прошёл syntax check, но само подключение к disposable YDB в этом окружении не запускалось; это не CI и не staging.

- Основные пользовательские сценарии этих 9 миграций представлены в RU-коде, но исходные Supabase-миграции нельзя применить к YDB. Остаётся отдельная работа по полноте соответствия всех 78 migrations, RPC, RLS, триггеров, семи Edge Functions, экранов и переходов.
- В RU-ветке источник upstream разделён: часть сценариев реализована, часть сознательно имеет безопасный ручной аналог из-за бесплатного лимита. Это не полная копия поведения `main` и не доказательство готовности для реальных пользователей.
- Российский staging не поднят: нет проверенной гарантии расхода 0 ₽, настроенных Yandex OAuth, YDB, S3, домена/хоста. Реальные аккаунты и данные учеников не использовались.
- До исправления отсутствующих звеньев, независимого security review и staging QA публикация и подключение реальных данных остаются закрыты.

## Обновление upstream от 20 ноября 2026

`main` продвинулась от `5e749c56` до `af1f0086` двумя коммитами. Перенос интерфейса FAM (#123, `5496264`) добавляет touch-навигацию, карточки Afisha для анонсов и опросов и показывает Afisha при пустых объявлениях. Российский shell пока имеет доску и отдельную школьную ленту, но не переносит полный layout/навигацию и эту Afisha-композицию; это известный функциональный/UI пробел. Новый workflow синхронизации production-доменов (`.github/workflows/fam-domain-sync.yml`) не переносится в российский staging, так как относится к production-доменам и не является пользовательской функцией FAM.

В актуальном `main` по дереву GitHub найдено 78 SQL migrations и 7 Edge Function entrypoints. Данная таблица остаётся ограниченным crosswalk и не подтверждает проверку полного актуального дерева.
