## Проверенные факты

- Supabase проект активен, регион `eu-central-1`, PostgreSQL 17.11. В актуальной истории миграций присутствуют queue bridge, retry recovery, producer schedule и cron retry reaper.
- Активны функции `fam-agent-worker` v17 и `fam-agent-coder-bridge` v1; bridge отвечает за узкое claim/finish API, но не выполняет модель сам.
- Активны 6 расписаний `fam-agent-*` и отдельный минутный worker проверки изображений. На снимке 13 ноября 2026, 05:37 UTC последние запуски всех 7 были `succeeded`; worker — каждые 5 минут, аудит ошибок сайта — ежечасно, producer coder и ежедневный digest — раз в сутки.
- Свежий read-only снимок production queue на 13 ноября 2026, 05:37 UTC: 78 задач — 75 `completed`, 3 `failed`; для `coder_patch_request`: 1 `completed`, 3 `failed`. Запрашивались только сгруппированные количества, без payload/описаний. Migration `20261113100000` bounded retry не применена.
- GitHub Actions run [#43362562139](https://github.com/spartakdubov059/fam-website/actions/runs/43362562139) завершился зелёным как запуск инфраструктуры модели, но Queue claim сообщил `No queued coder task`; поэтому `verify` и `prepare_review` были пропущены. Это не подтверждает создание patch или PR.
- Открытые PR #65 (точные операции редактирования) и #64 (Mellum) основаны на более ранней версии `main`. PR #65 остаётся mergeable draft и содержит exact-edit helper, тесты QA/Reviewer/Security/Performance и ролевую таблицу. Синтетический Qwen run [#43371755985](https://github.com/spartakdubov059/fam-website/actions/runs/43371755985) подготовил реальный patch, независимый QA применил его к чистому checkout и прошёл regression. В CI [#43375537883](https://github.com/spartakdubov059/fam-website/actions/runs/43375537883) все 217 moderation/security тестов прошли. Намеренно failing patch был отклонён во временном репозитории; дорогой smoke workflow запускается вручную.
- Draft PR #74 содержит ограниченный retry/cooldown для coder task. Его отдельный PostgreSQL 17 integration run [#43371083848](https://github.com/spartakdubov059/fam-website/actions/runs/43371083848) прошёл: первая временная ошибка ставит задачу обратно с задержкой, последняя попытка закрывает её, повторы сигнатуры ограничены недельным cooldown, просроченные/ручные задания и `anon` не получают доступ. Миграция не применялась к production.
- Supabase performance advisors (13 ноября 2026, 05:49 UTC) выдали 4 предупреждения о FK без покрывающего индекса (включая новые таблицы очереди изображений и школьных опросов) и 24 предупреждения о неиспользуемых индексах. Это advisory статистика короткого периода наблюдения, не доказательство необходимости менять схему; индексы/production не менялись.
- Свежая Supabase security advisor проверка (13 ноября 2026, 05:37 UTC) сообщает: `pg_net` установлен в `public`; `report_fam_site_error` доступен `anon`; четыре таблицы с RLS не имеют политик; четыре школьных RPC имеют `SECURITY DEFINER` и исполняются `authenticated`; также выключена Auth leaked-password protection. [Advisor: pg_net](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public), [advisor: public SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [advisor: signed-in SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [Auth leaked-password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- Дополнительные read-only catalog проверки подтвердили, что `private.avatar_image_moderation_queue` и три `public.fam_school_*` таблицы не дают прямого `SELECT` ролям `anon`/`authenticated`; доступ реализован через RPC. `fam_pulse_feed`, `fam_vote_school_poll`, `fam_publish_school_announcement`, `fam_publish_school_poll` требуют `auth.uid()`; операции публикации также проверяют роль `school_admin`/`council_member`. Это объясняет часть lint-предупреждений, но не заменяет ручной аудит функций и их будущих изменений.
- `report_fam_site_error` намеренно оставлен вызываемым от `anon` для браузерной телеметрии; его код принимает только перечисленные event/page значения и пишет ограниченные агрегированные счётчики без IP, текста ошибки или пользовательских данных. Остаточный риск — ложное увеличение счётчиков публичным вызовом. `pg_net` и Auth protection требуют отдельного решения владельца; в этой задаче Auth/RLS, grants и production не менялись.
- GitHub ruleset «FAM — защита main» активен и не имеет bypass actors, но `required_approving_review_count=0`. Следовательно, правила защищают прямые push и требуют PR/status check, однако сами по себе не доказывают одобрение владельцем.

## Следующий безопасный этап

1. На отдельном безопасном synthetic задании доказать путь queue claim → Qwen patch → независимые тесты и четыре отчёта → draft PR; живой coder run #49 не получил задание, поэтому этот путь ещё не подтверждён end-to-end.
2. Подготовить единый ежедневный русский отчёт из фактических job/queue/Supabase состояний, не смешивая отсутствующие и успешные результаты.
3. Устранить/доказать серверный owner approval gate и минимальные права Actions; текущий GitHub ruleset требует 0 одобрений.
4. Отдельно проверить Supabase advisor findings и безопасность `pg_net` по исходным миграциям; не менять Auth/RLS/production.
5. Не объединять PR и не публиковать production; bounded retry migration #74 не применена.
