# Фоновые задания FAM RU в Yandex Cloud Functions

## Зачем нужен отдельный вход

`deploy/package-yandex-function.mjs` упаковывает два обработчика: `index.handler` для публичного API и `timer.handler` для Cloud Functions Timer trigger. Их следует развернуть как **две разные Cloud Functions**. К функции `timer.handler` нельзя подключать публичный API Gateway; вызывать её должен только сервисный аккаунт триггера с ролью `functions.functionInvoker` на эту функцию.

Обработчик принимает только один пакет Yandex Timer event, проверяет `event_type`, `cloud_id`, `folder_id`, точный `trigger_id` и совпадение `details.payload` с заданием из серверной allowlist. Для фонового runtime достаточно YDB и, для медиа-заданий, приватного S3-конфига; OAuth client/session secrets пользователя не нужны. Handler возвращает только ограниченные счётчики, даты и статусы, закрывает соединения и скрывает внутренние ошибки.

## Подготовленные задания

Время выражений — UTC, формат Yandex Timer: `Minutes Hours Day-of-month Month Day-of-week Year`.

| Задание | Cron | Payload | Примечание |
|---|---|---|---|
| Безопасный фоновый worker | `0/5 * * * ? *` | `safe_agent_worker` | Только allowlisted агрегатные задачи; произвольный код и модели не запускаются. |
| Производитель безопасных coder-задач | `10 3 * * ? *` | `coder_task_producer` | Не запускает Qwen и не исполняет код. |
| Сводка школьных задач | `30 3 * * ? *` | `school_agent_report` | Рассчитывает ограниченные школьные агрегаты. |
| Проверка фоновых зависимостей | `40 3 * * ? *` | `runtime_health` | Проверяет соединение с YDB и наличие конфигурации S3; не является live-проверкой доступности бакета или OAuth. |
| Суточная сводка оркестратора | `0 4 * * ? *` | `orchestrator_daily_digest` | Идемпотентная очередь агрегированных данных. |
| Очистка незавершённых медиа | `17 0,6,12,18 * * ? *` | `pending_media_cleanup` | Удаляет только объекты, заранее заявленные YDB; требует приватный S3. |
| Сводка ошибок сайта | `0,15,30,45 * * * ? *` | `site_error_digest` | Обрабатывает только сохранённые агрегаты; совпадает с исходным шагом cron в 15 минут. |
| Восстановление незавершённых удалений | `0/15 * * * ? *` | `account_deletion_recovery` | Дополнительное задание RU: восстанавливает очередь после сбоя, удаляет только учтённые медиа аккаунта; требует YDB и приватный S3. |

Значения выражений перенесены с подготовленных RU расписаний systemd, кроме дополнительного восстановления удалений каждые 15 минут. В systemd timer trigger используется новый планировщик, поэтому проверка состояния и свежести установленных systemd-служб не подходит для Yandex Cloud и не включается в результат Cloud Function health job.

## Настройка окружения функции-триггера

После создания триггеров задайте в отдельной функции-триггере:

```json
{
  "FAM_RU_CLOUD_ID": "<ID_облака>",
  "FAM_RU_FOLDER_ID": "<ID_каталога>",
  "FAM_RU_TIMER_TRIGGER_JOB_MAP": "{\"<ID_триггера_1>\":\"safe_agent_worker\",\"<ID_триггера_2>\":\"pending_media_cleanup\"}"
}
```

Для каждого таймера создайте отдельный trigger с payload, равным указанному имени задания. Добавьте его фактический trigger ID в карту и выпустите новую версию функции. При смене/удалении триггера удалите его ID из карты. Не добавляйте в карту произвольные значения: код отклоняет неизвестные задания и непредусмотренные события до открытия YDB.

Сервисному аккаунту Timer trigger дайте только право вызывать timer-функцию. Отдельному runtime service account выдайте только необходимые права YDB и приватного бакета. Не выдавайте trigger account доступ к базе или бакету и не направляйте API Gateway в timer-функцию.

## Проверка и ограничения

- Unit-тесты используют синтетические Timer events и подставной runtime, не обращаются в Yandex Cloud.
- Перед созданием триггеров необходимо проверить точные cloud/folder/trigger IDs и роли в целевом аккаунте, а затем запустить одноразовый synthetic YDB/S3 integration.
- Yandex Cloud free tier включает лимит вызовов Cloud Functions, но после его превышения начисляется плата; Billing budget не останавливает потребление. Поэтому эти расписания пока не включать при обязательном бюджете строго `0 ₽`. Документы: [формат события Timer](https://yandex.cloud/ru/docs/functions/concepts/trigger/timer), [создание Timer trigger](https://yandex.cloud/ru/docs/functions/operations/trigger/timer-create), [free tier](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier), [бюджеты](https://yandex.cloud/ru/docs/billing/concepts/budget).
- Cloud resources, triggers, API Gateway и реальные данные этим файлом или кодом не создаются.
