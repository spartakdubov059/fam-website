# Сверка квоты сообщений FAM RU — 21 ноября 2026

В upstream SQL `20261108004943_enforce_server_side_content_moderation.sql` сообщения ограничены восемью отправками на пользователя за минуту. В RU delivered-сообщения уже использовали эту квоту, но сообщения, отправленные на ручную проверку, шли через отдельную выборку «до пяти за сутки». Она была неэквивалентна и не учитывала общий поток сообщений.

Теперь `createPendingMessage` проверяет участников школы и расходует тот же транзакционный квотный счётчик `message`, что и прямая доставка. Отдельный лимит 5/24ч удалён. Тело сообщения по-прежнему остаётся закрытым от получателя до решения модератора школы.

Проверки на Node 22.15.0:

- Полный backend suite: **416/416**.
- Новый тест проверяет восемь pending-сообщений, отказ девятого и общий лимит при смешивании pending и delivered.
- Disposable YDB integration дополнен синтетической проверкой, что pending-сообщение расходует квоту `message`; сам сценарий здесь не запускался — Docker/Podman/YDB отсутствуют.
- `node --check ru-migration/compat/integration-ydb.mjs`, `ru-migration/compat/verify.mjs` и `git diff --check` прошли.

Изменения локальные в изолированной ветке. GitHub Actions и российское cloud staging для этого коммита не запускались; main, production, настоящие аккаунты и данные учеников не использовались.
