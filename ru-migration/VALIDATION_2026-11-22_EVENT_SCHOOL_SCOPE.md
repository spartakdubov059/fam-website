# Проверка границы школы при регистрации на события — 22 ноября 2026

## Найденный дефект

Офлайн-аудит изолированного снимка `migration/yandex-cloud` выявил, что POST регистрации на событие передавал в YDB только ID ученика и UUID события. Репозиторий проверял состояние и вместимость события, но не сравнивал школу ученика со школой события. При известном UUID ученик другой школы мог создать регистрацию, занять место или создать заявку, которая скрывается фильтром школьной очереди.

Машиночитаемый отчёт Codex Security: `/Users/spartakdubov/.codex/state/plugins/codex-security/scans/fam-ru-clean-5e7/unversioned_20261122T152240Z_vujvbjf5/report.md` (scan `8fff8e3b-8b5c-4a90-b816-83d1e79bebf3`). Средняя серьёзность. Доступность UUID чужого события через действующий интерфейс не установлена.

## Исправление

- API передаёт подтверждённый `school_id` активного профиля вместе с ID ученика.
- Репозиторий сравнивает школу актёра со школой события в транзакции до изменения вместимости. Несовпадение возвращает безопасный ответ `event_unavailable`.
- Добавлены unit и synthetic YDB проверки: другой школьный профиль получает отказ, счётчик мест не меняется; обычная регистрация в своей школе сохраняется.
