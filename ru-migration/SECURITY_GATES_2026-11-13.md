# FAM RU: публичные URL после модерации (13 ноября 2026)

Этап подготовлен в изолированном локальном комплекте. **В main ничего не переносить без тестов.**

## Ошибка
До исправления серверный YDB-репозиторий принимал любой `https://...` URL в поле `image_url` при завершении задачи проверки фото. Даже если сам обработчик обычно создаёт корректную ссылку, такая проверка не запрещает внешние домены и URL другого объявления.

## Исправление в локальном комплекте
- Параметр `publicMediaBaseUrl` обязателен при создании `createYdbImageModerationRepository` и передаётся из `createImageModerationWorkerRuntime`.
- При `status=approved` URL должен в точности соответствовать `FAM_PUBLIC_MEDIA_BASE_URL/listings/<listing UUID>/<image UUID>.webp`.
- Проверяются точный HTTPS origin и базовый путь, отсутствуют URL credentials, query/fragment, другая схема, порт, percent-encoded segment и посторонний хост.
- Отсутствующая/небезопасная конфигурация блокирует создание обработчика, а недопустимый URL отклоняется до YDB-транзакции.
- Ручная модерация, прочие статусы и данные пользователей не меняются.

## Проверка
Локальный `npm run check`: **220/220 PASS**, включая 4 новых теста (посторонний хост/путь, невалидная конфигурация, runtime fail-closed, корректный media base с подкаталогом). Применимость патча к локальной версии 216/216 проверена через `patch --dry-run`.

**Ограничение:** текущая ветка GitHub пока содержит технические записи и отдельные вспомогательные файлы, а полный локальный код находится в отдельном архиве. Этот документ сам по себе не внедряет проверку URL в выполняющийся GitHub-код.
