# Проверка условия «только бесплатно» для FAM RU staging

Дата проверки: 20 ноября 2026 г. Источники: официальные страницы Yandex Cloud, перечисленные ниже. Проверка касается публичных тарифных правил и не подтверждает состояние платежного аккаунта пользователя.

## Вывод

Публичный free tier может покрыть небольшую нагрузку на компоненты проекта в пределах месячных квот. Он не задаёт жёсткий предел расходов: после исчерпания квоты тарификация продолжается. Бюджет Yandex Cloud только уведомляет о пороге и не останавливает использование. Поэтому по доступным сведениям нельзя гарантировать 0 ₽ для облачного staging. Новый staging не создавался, подписка и платные ресурсы не включались.

На 6 ноября 2026 г. документация Yandex Cloud указывала, что пробный период и вводный грант недоступны новым клиентам; пробный период был ограничен организациями с оплатой банковским переводом. Это не доказывает, какой режим применим к платежному аккаунту пользователя.

## Квоты, связанные с FAM RU

Официальный free tier документ указывает месячные не тарифицируемые объёмы:

- YDB: 1 млн операций в Request Units, 1 ГБ хранения и две полные автоматические резервные копии.
- Object Storage Standard: 1 ГБ хранения, 10 тыс. PUT/POST/PATCH/LIST и 100 тыс. GET/HEAD/OPTIONS.
- Serverless Containers: 1 млн вызовов, 10 ГБ×час RAM и 5 vCPU×час.
- API Gateway: 100 тыс. запросов.
- Cloud Functions: 1 млн вызовов и 10 ГБ×час.
- Cloud Logging: 5 ГБ записи и 1 ГБ хранения.

Квоты относятся к платёжному аккаунту и суммируют использование всех привязанных организаций/облаков; месячный остаток сбрасывается. После превышения бесплатного объёма начинает действовать тариф соответствующей услуги.

## Барьер для автоматического безопасного staging

Yandex Cloud Budget не является ограничителем: достижение установленного порога не влияет на дальнейшее потребление. Автоматический триггер остановки ВМ существует как отдельная настройка, но сам по себе не доказывает жёсткого нулевого расхода для API Gateway, YDB, Object Storage, функций, логирования, трафика и задержки обработки события.

Чтобы считать staging разрешённым в рамках пользовательского ограничения, сначала нужна проверка конкретного аккаунта и ресурсов в его консоли: доступность всех нужных сервисов, способ оплаты/статус пробного периода, фактические остатки квот и отсутствие уже связанного потребления в других проектах. Даже после этого нужен жёсткий лимит/автоматическое прекращение потребления для каждого тарифицируемого компонента; одних бюджетных уведомлений недостаточно. Пока это не подтверждено, допустимы только локальные проверки с синтетикой.
