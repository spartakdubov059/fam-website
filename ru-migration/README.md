### Совместимость загрузки фото с Yandex API Gateway — 23 ноября 2026

Yandex API Gateway ограничивает размер запроса и ответа 2,5 МБ ([официальные лимиты](https://yandex.cloud/ru/docs/api-gateway/concepts/limits)). Поэтому перед отправкой объявления браузер локально сжимает выбранное фото до WebP не более 2 МБ: исходное изображение не отправляется внешнему обработчику, сохраняется лимит исходного файла до 5 МБ, сервер повторно проверяет и обрабатывает результат. Backend адаптивно уменьшает WebP до 2 МБ и отказывается сохранять/отдавать больший объект, так что и фотоответы проходят через тот же шлюз. При невозможности уложиться в лимит загрузка останавливается до сетевого запроса. `listing-submit-ui.test.mjs`, `pending-images.test.mjs` и `s3-pending-store.test.mjs` проверяют сжатие, отказ при недостижимом размере и ограничение выдаваемого файла; облачная интеграция ещё не проверялась.

Дополнительная проверка 23 ноября нашла, что ответ S3 мог превышать заявленный `Content-Length`: прежний адаптер сначала целиком собирал поток и только потом сравнивал размер. Исправление читает тело потоком и прекращает чтение при превышении 2 МБ. Тест покрывает ложный короткий `Content-Length` и подтверждает, что последующие части потока не читаются. Это защита локального адаптера; облачный S3 endpoint не проверялся.

Исправление и потоковые тестовые адаптеры проверены в точном коммите [`6550992`](https://github.com/spartakdubov059/fam-website/commit/655099268ab12cadcf8be97ba95c7f5e3754afb1): [Node 22 SDK/Sharp CI #45121084540](https://github.com/spartakdubov059/fam-website/actions/runs/45121084540) — 509/509 backend/UI tests, package/Sharp/timers passed; [disposable YDB CI #45121084536](https://github.com/spartakdubov059/fam-website/actions/runs/45121084536) — synthetic schema/API/media tests passed and database container removed.
