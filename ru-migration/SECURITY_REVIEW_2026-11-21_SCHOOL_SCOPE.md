## Область

Это ограниченный review этих маршрутов; не полный repository security sign-off.

## Поток и контроль доступа

1. `GET /api/v1/listings` требует валидную identity и активный database actor с `school_id`; для гостя/отсутствующего профиля возвращает пустой список. В запрос передаётся только школа, взятая из actor.
2. `listActiveListings(schoolId)` отвергает пустой scope и параметризует `school_id` вместе с `status = 'active'`.
3. Одобренное фото активного объявления требует действующий профиль той же школы. Ожидающее фото выдаётся только школьному модератору той же школы после проверки suspension.
4. Счётчик event occupancy требует actor и в SQL ограничивает событие по той же школе, флагу события и активному статусу.
5. Web UI посылает same-origin cookie и предлагает вход гостю; список и счетчик не выполняют запросы с чужой школы, переданной клиентом.

- Cloud deployment, реальные аккаунты и данные учеников не использовались.
- Доступность/права Yandex ID, YDB и Object Storage в конкретном облачном аккаунте не проверены.
- Полный управляемый security scan репозитория не завершён; его сохранённый snapshot предшествует этой правке. Эта заметка не заменяет независимый scan всех auth, ролей, RLS-эквивалентов, фоновых задач, IAM и всех API-маршрутов.
