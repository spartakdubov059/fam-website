# FAM RU — изолированная миграция на российскую инфраструктуру

**Рабочая ветка: `migration/yandex-cloud`. Не сливать в main и не развёртывать на production.**

Цель — подготовить российскую копию FAM отдельно от действующего сайта. Ветка `main`, текущий FAM, Netlify/Supabase и реальные данные учеников не используются для этих проверок.

## Что уже реализовано в изолированном коде

- Отдельная копия статического интерфейса в `app/web`.
- Fail-closed HTTP backend с API подачи объявления и школьной идеи; идеи без доступной проверки сохраняются только как `pending` и не входят в публичные чтения.
- Избранное подключено к публичной доске: вошедшие пользователи добавляют и удаляют активные объявления; гости переходят на Яндекс ID, а записи выполняются только от подтверждённого профиля.
- API отправки личных сообщений: активный получатель должен быть из той же школы; сообщение сохраняется только после явного ответа модерации `ok`.
- OIDC bearer verification, разрешение ролей через профиль в YDB; дополнительно реализован серверный OAuth Яндекс ID с PKCE S256, одноразовой state-cookie, проверкой `client_id` профиля, часовым HttpOnly/SameSite cookie и logout. Для unsafe-запросов по cookie и logout требуется точное совпадение `Origin` с origin зарегистрированного callback.
- Маршрут школьной модерации объявления: права берутся из профиля YDB, решение ограничено школой объявления и переходом только из `pending`; используется транзакция YDB.
- Добавлен backend-модуль записи на мероприятия: открытые и ограниченные события, одно место на пользователя, транзакционная проверка вместимости, отмена своей записи, публичный счётчик без данных участников и решение владельца мероприятия с ролью школьного администратора/совета.
- Гостевая доска показывает дату и время мероприятия; пользователь может войти через Яндекс ID, записаться или отменить свою запись. Кнопки используют только same-origin запросы; HTML пользовательских полей не вставляется в DOM.
- YDB схема профилей и объявлений, параметризованный repository; добавлено публичное чтение только активных объявлений с ограниченным набором полей; `/api/v1/me` возвращает профиль из YDB только после проверки OIDC-токена.
- Локальные privacy/moderation gates; новые записи остаются `pending`, если проверка недоступна.
- API приватной загрузки изображений: только активный профиль, JPEG/PNG/WebP до 5 МБ, проверка формата и преобразование Sharp в WebP, серверный случайный ключ с префиксом пользователя и приватный S3-совместимый объект с шифрованием на стороне хранилища. Без S3-конфигурации маршрут возвращает 503.
- Форма российской копии загружает фото через тот же backend, привязывает приватный ключ к новому объявлению и отправляет объявление на проверку. Если запись объявления не удалась, браузер запрашивает удаление ещё не связанного файла; backend проверяет владельца и отсутствие ссылки из объявления. Отдельная очередь модерации показывает pending-объявления только школьному администратору/совету школы из его профиля; фото можно проверить и принять до публикации объявления. Публичная доска показывает только одобренное фото активного объявления через same-origin маршрут с `image/webp`, `nosniff` и `private, no-store`. Межшкольный доступ проверяется тестами. Периодическая уборка файлов, оставшихся после закрытия вкладки или потери сети, ещё не реализована.
- Российская форма позволяет отправить школьную идею через защищённый API; при недоступной проверке идея сохраняется только как `pending`. UI личных сообщений и проверка/модерация сообщений ещё не подключены.

### Подключение Яндекс ID (пока не настроено)

Для отдельного тестового домена нужно зарегистрировать приложение Яндекс OAuth типа «Для авторизации пользователей», добавить HTTPS Redirect URI `https://<тестовый-домен>/auth/yandex/callback` и минимальное право `login:info`. В переменные окружения backend передаются `FAM_RU_YANDEX_CLIENT_ID`, `FAM_RU_YANDEX_REDIRECT_URI` и случайный `FAM_RU_SESSION_SECRET` длиной не менее 32 байт. Секреты не записывать в репозиторий или frontend. Для разработки допустим только `localhost` без HTTPS; удалённый адрес без HTTPS отклоняется.

Обмен кода и запрос профиля выполняются сервером. OAuth-токен не сохраняется и не передаётся в URL; браузеру выдаётся только подписанная краткоживущая HttpOnly cookie. Роли выдаются исключительно из `fam_user_profiles`; сам вход не создаёт профиль и не назначает роль. Для неизвестной личности доступна заявка на школьный профиль: каталог школ задан на сервере, пользователь не выбирает роль, новый профиль появляется только после решения администратора той же школы, и всегда получает роль `student`. Решение и приватные интеграционные сценарии проверены на синтетических данных в CI. Реальная регистрация OAuth-приложения и внешний вход не проверялись.

Эти части ещё не образуют полный перенос FAM. Требуются перенос и аудит всех исходных функций, SQL/RLS, ролей и фоновых задач, а также проверка всей пользовательской навигации и сценариев.

## Неподтверждённое / блокеры

- Архив `FAM_RU_Migration_Starter_2026-11-13_220tests.zip` в предыдущем чате дан временной ссылкой `sandbox:/mnt/data`, но вложения в истории нет и сам файл отсутствует в workspace. SHA архива и **220 тестов** независимо не воспроизведены; подтверждены 111 текущих backend-тестов в CI.
- Реального российского облачного staging нет. Яндекс ID flow проверен только mock-тестами: нет зарегистрированного OAuth-приложения, redirect URI, активного профиля/онбординга и конфигурации backend. Облачные YDB, объектное хранилище, реальный OAuth, расходы и сетевые политики не проверялись.
- Семь исходных Edge Functions, 69 SQL миграций и расписания `pg_cron` перенесены не полностью; см. `PORTING_INVENTORY.md` и `CRON_PORTING.md`.
- Российский вход не готов для реальных пользователей: OAuth-приложение не зарегистрировано, а первичный доступ проверен только синтетически. Есть безопасная заявка на профиль, но каталог содержит только две школы, найденные в текущем UI; прежде чем расширять его, нужно подтвердить полный список. Не подключены UI личных сообщений, управление профилем, аватары, заявки на админские роли, удаление аккаунта и большая часть школьских панелей.
- Яндекс ID и российская база не настроены в реальном окружении. Поэтому экран записи и API проверены на синтетических данных в CI, но реальный вход пользователя пока невозможен.
- Никакие платные ресурсы и trial не запускались. У Yandex Cloud бесплатные объёмы ограничены месячными квотами: после их превышения начисляется плата. Бюджетные пороги только уведомляют и сами по себе не останавливают потребление. Поэтому при требовании строго 0 ₽ облачные ресурсы не создаём; используем только локальную эмуляцию, пока нет подтверждённого способа гарантировать отсутствие списаний. См. [Free tier](https://yandex.cloud/ru/docs/billing/concepts/serverless-free-tier) и [бюджеты](https://yandex.cloud/ru/docs/billing/concepts/budget).
