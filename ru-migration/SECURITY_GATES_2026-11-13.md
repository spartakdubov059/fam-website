# FAM RU: публичные URL после модерации (13 ноября 2026)

Этап подготовлен в изолированном локальном комплекте. **В main ничего не переносить без тестов.**

## Ошибка
До исправления серверный YDB-репозиторий принимал любой `https://...` URL в поле `image_url` при завершении задачи проверки фото. Даже если сам обработчик обычно создаёт корректную ссылку, такая проверка не запрещает внешние домены и URL другого объявления.

## Исправление в локальном комплекте
- Параметр `publicMediaBaseUrl` обязателен при создании `createYdbImageModerationRepository` и передаётся из `createImageModerationWorkerRuntime`.
- При `status=approved` URL должен в точности соответствовать `FAM_PUBLIC_MEDIA_BASE_URL/listings/<listing UUID>/<image UUID>.webp`.
- Проверяются точный HTTPS origin и базовый путь, отсутствуют URL credentials, query/fragment, другая схема, порт, percent-encoded segment и посторонний хост.
- Отсутствующая/небезопасная конфигурация блокирует создание обработчика, а недопустимый URL отклоняется до YDB-транзакции.
- Ручная модерация, прочие статусы и данные пользователей не меняются.

## Проверка
Локальный `npm run check`: **220/220 PASS**, включая 4 новых теста (посторонний хост/путь, невалидная конфигурация, runtime fail-closed, корректный media base с подкаталогом). Применимость патча к локальной версии 216/216 проверена через `patch --dry-run`.

**Ограничение:** текущая ветка GitHub пока содержит технические записи и отдельные вспомогательные файлы, а полный локальный код находится в отдельном архиве. Этот документ сам по себе не внедряет проверку URL в выполняющийся GitHub-код.

## Дополнение: статическая проверка безопасности (17 ноября 2026)

На исходном снимке кода аудит подтвердил, что перечисленные ниже защитные границы присутствуют в коде; это не доказывает корректность настроек ещё не созданного облачного окружения.

- В backend FAM RU проверены сессии Яндекс ID/OIDC, привязка ролей к профилю в YDB, операции по школе, загрузка и выдача медиа, очередь удаления, телеметрия и фоновые процедуры. В просмотренных путях не обнаружено подтверждённого обхода авторизации или межшкольного доступа. Анонимная телеметрия ограничена 60 запросами в минуту на процесс; это ограничение не является общим лимитом для нескольких реплик.
- Отдельно просмотрены исходные `fam-agent-worker`, `fam-agent-coder-bridge` и `fam-listing-image-worker`, очереди и сценарий локального кодера. По этим исходникам не найден путь анонимного вызова, пользовательская телеметрия не управляет привилегированными файлами кодера, а lease ограничивает работу устаревших обработчиков. Этот обзор исходных компонентов не означает, что они уже перенесены в RU-копию.
- Если настроить автоматическую проверку изображений исходного FAM, её обработчик отправляет текст объявления и подписанные ссылки на ожидающие изображения во внешний OpenAI Moderation API. В RU-копии такой классификатор не подключён; школьная проверка выполняется вручную. Перед любым использованием реальных данных нужно отдельно утвердить этот внешний поток.
- Проверка статическая и относится к снимку `7b28bcd2fd7ae16d637e3e3e9c5816dcbfc80f74`; исправление лимита телеметрии и readiness OIDC проверено в последующих CI коммитах `a9d6464` и `8b61a48`. Полный аудит актуального `HEAD`, облачная конфигурация IAM/bucket/OAuth и живой staging остаются непроверенными.

Источники CI: [SDK/Sharp 264/264](https://github.com/spartakdubov059/fam-website/actions/runs/44130259860) и [одноразовая YDB интеграция](https://github.com/spartakdubov059/fam-website/actions/runs/44130259874).
